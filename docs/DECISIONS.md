# Decision Log — Panta Signal

## D-001 — Dedicated Public Repository
**Status:** accepted

Panta Signal lives in `uknwplayer/panta-signal` as a standalone project rather than being embedded in ARCA or Nano JSON Lens 402.

## D-002 — English as Official Repository Language
**Status:** accepted

All repository artifacts, source code, comments, API fields, public errors, issues, releases, and public-facing communication use English. Portuguese may be used in private operator conversation.

## D-003 — Mandatory Checkpoint Per Work Block
**Status:** accepted

Every work block ends by updating `docs/checkpoints/CHECKPOINT_CURRENT.md`. Material milestones also receive a historical checkpoint snapshot.

## D-004 — Product Is an Intelligence Layer, Not a Generic Dashboard
**Status:** accepted

Panta Signal is designed to convert prediction-market observations into ranked, explainable intelligence rather than merely mirror market pages.

## D-005 — Deterministic Signals Before AI Explanation
**Status:** accepted

Numerical signals, scores, and rankings must be generated by deterministic/versioned logic. The AI Analyst explains or queries structured results but is not the source of truth for calculations.

## D-006 — No Trading or Capital Movement in Initial MVP
**Status:** accepted

Real-money trading, swaps, autonomous execution, wallet custody, private keys, and fund movement are outside the initial MVP. Any future transactional capability requires a separate design and security review.

## D-007 — Explicit Provenance Classes
**Status:** accepted

The system distinguishes:
1. external/source data;
2. deterministic derived data;
3. AI-generated interpretation.

Material signals must preserve enough metadata to trace calculations back to source observations.

## D-008 — Nano Documentation Pattern as Reference, Extended for Competition
**Status:** accepted

The repository adopts the strongest continuity mechanisms from `nano-json-lens-402` — README, whitepaper, architecture, roadmap, security, decisions, execution ledger, operations, continuity rules, and checkpoints — and adds first-class product, provenance, signal, evaluation, hackathon, and submission documents.

## D-009 — Documentation Foundation Before Product Code
**Status:** accepted

The repository establishes durable product/continuity/security documentation before live API integration or application implementation. Documentation must not be treated as proof that implementation exists.

## D-010 — Isolated Foundation Branch
**Status:** accepted for current execution

The documentation foundation is executed on `docs/foundation-2026-09-26` rather than directly on `main`, so the complete foundation can be reviewed before integration.

## Open Decisions

The following remain intentionally open:
- exact authoritative Panta API endpoints and schemas;
- authentication/key lifecycle and rate limits;
- runtime/deployment provider;
- persistent storage provider/schema technology;
- exact signal formulas and thresholds;
- related-market matching/clustering method;
- AI model/provider and tool interface;
- public API shape, if any;
- license;
- long-term data retention policy;
- whether watchlists require persistent user accounts in the MVP.

Open decisions must not be silently resolved through implementation. They require evidence and an explicit decision entry when material.
