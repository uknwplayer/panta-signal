**Date:** 2026-09-27

## Completed

- Added `panta_signal/providers/panta.py` with authenticated GET-only methods for categories, one market-list page, one market detail, and one market trade-tape response.
- Bounded list calls to 1–50 records and trade-tape calls to 1–200 records. Pagination is caller-controlled; no automatic follow-up request occurs.
- The client preserves source market objects and their present field names. It does not synthesize omitted fields. Explicit null/absent cursor state is retained; empty trade arrays are valid.
- The API key is passed to cURL through configuration on stdin, not in the URL or cURL argument list. HTTP error messages omit response bodies.
- Added six offline tests using synthetic responses and a fake cURL runner.
- The full local suite passed: 19 tests on Python 3.12.14.

## Limits

The new provider has not itself called the live API. The operator's prior live reads used Termux cURL and validated status codes/routes, but the new code still needs an on-device smoke test with the local test key. The live sample is narrow: one primary market, one sparse detail, one null cursor, and an empty trade tape. Do not claim full live compatibility or populated trade-row validation.

No secret, market ID, title, wallet address, signature, or raw payload was committed. No write, quote, trading, signing, claim, or capital-moving route exists in the client.
