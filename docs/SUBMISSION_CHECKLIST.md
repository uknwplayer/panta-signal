# Submission Checklist — Panta Signal

This checklist must remain conservative: an item is checked only after evidence exists.

## A. Official Rules
- [ ] Current official competition page revalidated.
- [ ] Eligibility rules recorded from an authoritative source.
- [ ] Final deadline/date/timezone recorded.
- [ ] Judging criteria/weights recorded.
- [ ] Required submission fields recorded.
- [ ] Required demo/video format recorded.
- [ ] Repository/public-source requirements recorded.
- [ ] Cross-submission/duplicate-entry rules recorded.
- [ ] Prize/payout terms recorded.

## B. Repository Quality
- [ ] README accurately reflects current state.
- [ ] Current checkpoint and roadmap are current.
- [ ] Public setup instructions reproduce the working build.
- [ ] License decision completed if required.
- [ ] No dead links in required documentation.
- [ ] Secret scan completed.
- [ ] No real credentials in repository history used for submission.
- [ ] Tests/checks required by the implemented stack pass.
- [ ] Build/version used for submission identified.

## C. Panta Integration
- [ ] Authoritative API contract documented.
- [ ] Authentication works using server-side secrets.
- [ ] Core market-data flow demonstrated end to end.
- [ ] Upstream timestamps/identifiers preserved.
- [ ] Failure/stale-data behavior visible.
- [ ] Demo evidence clearly shows Panta-backed functionality.

## D. Signal Engine
- [ ] At least one meaningful signal family implemented and tested.
- [ ] Signal formula/version documented.
- [ ] Missing/stale-data behavior tested.
- [ ] Provenance visible from signal to source observations.
- [ ] Ranking behavior evaluated with fixtures/real samples.
- [ ] No unsupported predictive-accuracy/statistical claims.

## E. Dashboard / UX
- [ ] Public dashboard loads from a clean browser session.
- [ ] Main value proposition is understandable quickly.
- [ ] Ranked signals are easy to locate.
- [ ] Market/signal detail explains what changed and when.
- [ ] Provenance/timestamps are visible.
- [ ] Mobile-browser usability checked.
- [ ] Loading/error/stale states are understandable.

## F. AI Analyst
- [ ] AI provider/tool interface finalized.
- [ ] Core questions work over structured records.
- [ ] Supporting evidence is surfaced.
- [ ] Unsupported/missing-data cases do not become fabricated facts.
- [ ] Prompt-injection behavior from source text evaluated.
- [ ] AI remains downstream of deterministic signal calculations.

## G. Deployment and Operations
- [ ] Public HTTPS deployment reachable.
- [ ] Production secrets configured outside source control.
- [ ] Health/reachability check verified.
- [ ] Database/persistence verified where required.
- [ ] Panta upstream failures tested.
- [ ] AI provider failure behavior tested.
- [ ] Demo build/commit recorded.
- [ ] Final public URLs verified immediately before submission.

## H. Demo Assets
- [ ] Demo narrative/script finalized.
- [ ] Screenshots captured from final build if required.
- [ ] Video recorded if required.
- [ ] Video length/format validated against official rules.
- [ ] Demo shows: market movement -> signal -> provenance -> AI explanation.
- [ ] Demo avoids claiming unimplemented or unverified capabilities.

## I. Judging Traceability
- [ ] Every verified judging criterion mapped in `HACKATHON_CRITERIA.md`.
- [ ] Repository evidence identified for each criterion.
- [ ] Demo evidence identified for each criterion.
- [ ] Remaining gaps resolved or explicitly disclosed.

## J. Final Submission
- [ ] Submission form completed with final URLs/assets.
- [ ] Project description matches actual shipped behavior.
- [ ] Required team/operator details verified.
- [ ] Submission reviewed from a judge’s perspective.
- [ ] Submission sent before authoritative deadline.
- [ ] Confirmation/reference captured.
- [ ] Confirmation recorded in execution ledger and checkpoint.

## Current State

All submission gates are currently unchecked because the product has not yet been implemented, deployed, externally revalidated, or submitted.
